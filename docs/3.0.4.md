# 3.0.4：HTML 手机布局与短代码 Markdown 修复

HTML 文档中的嵌套 Grid 容器默认使用内容的最小宽度。长代码、长链接或原始尺寸较大的媒体会把上层网格一起撑宽，即使 iframe 已按手机屏幕正确缩小，正文仍可能溢出。

主题现在仅在隔离文档内部提供低优先级的布局默认值：普通块级容器可以收缩，长文本可以换行，代码保留原有空白并在自己的区域内横向滚动，媒体宽度限制在所在容器内。作者的显式 CSS 可以覆盖这些默认值，不改变原始 HTML 文件或文章内容，不使用整体缩放或隐藏溢出的方式裁切正文。布局样式在服务端注入，禁用脚本时同样生效。

参考文章在 390px 屏幕下的文档宽度由溢出的约 683px 恢复到可用的 350px；桌面排版尺寸保持一致。回归覆盖 320px、390px、844px、1440px、旋转与重新加载、嵌套网格、长代码的实际滚动、导航项不重叠、图片比例、作者样式优先级和关闭 JavaScript。

主题仍不会自动重写作者显式设置的固定列宽、最小宽度或断点。复杂图表和特定排版需要文档自身提供相应的响应式设计。

WP Githuber MD 在保存文章时会原样保留短代码及其正文，主题以前只展开短代码，因此内部的 Markdown 会显示为原始标记。现在主题在 WordPress 自动排版和短代码展开之前，使用该文章的 Githuber 解析器处理这些正文：`collapse`、`fold`、`alert`、`admonition` 支持标题、列表、链接、代码块等块级内容；`label`、`checkbox`、`progressbar`、`hidden`、`spoiler` 和 `ref` 支持行内 Markdown。

适配仅应用于 Githuber Markdown 文章，普通编辑器内容保持原有处理流程。嵌套容器按各自格式处理，代码示例与转义声明不执行，`nested="false"` 继续保留内部短代码文本；`timeline`、友链等结构化数据仍使用原有语法。生成的 HTML 经 WordPress KSES 过滤，独立解析器不会更改插件的共享安全设置。无需重新保存已有文章。

本版本也包含 3.0.3 发布后的 CI 修复：浏览器测试等待 Playground 完成全部初始化步骤，并使用规范化路径创建测试输出目录，确保全新检出时可以运行。
