# 3.0.3：图片与官方性能插件兼容

首页封面短暂出现后消失，原因是主题给图片写入了内联 `opacity: 0`，淡入动画结束后又恢复透明。旧懒加载逻辑还删除了图片以及 `<picture><source>` 的 `srcset`，使响应式候选和现代格式失效。现在封面、首图和相关文章保留 WordPress 生成的完整图片 HTML，交给浏览器和原生加载策略处理；历史 `data-original` 标记仍可正常加载。

WP Githuber MD 把 Markdown 转换为 HTML 存入文章正文，但图片常只有 URL，没有 `wp-image-ID`。WordPress 无法关联附件，自然无法补齐尺寸、响应式候选和插件元数据。主题现在在核心正文图片过滤器之前，为可确认的本站媒体库图片补上附件身份。识别经过附件元数据验证，支持原图、注册的子尺寸、缩放后的原图和已有现代格式文件，并缓存解析结果。不会修改文章或 Markdown 源码，也不会下载外链图片或猜测 AVIF/WebP 地址。

文章封面和配置的 Banner 图片改由原生图片标签输出，保留裁切和尺寸，关闭 JavaScript 后也能显示。正文经典图片继续保持原来的留白；核心图片区块保留自己的布局与灯箱。Modern Image Formats 的 `picture` 包装在核心灯箱中具有可测量的尺寸，避免放大按钮偏出手机屏幕。

## 各插件的实际边界

| 插件 | 主题的处理与必要条件 |
| --- | --- |
| [Modern Image Formats](https://wordpress.org/plugins/webp-uploads/) | 本站媒体库的 Markdown 图片、特色图、首图与 Banner 均进入附件图片过滤流程，支持替换 URL 和 picture 模式。相应格式文件必须已生成；旧图片可能需要重新生成，外链不由插件自动转换。 |
| [Image Placeholders](https://wordpress.org/plugins/dominant-color-images/) | 保留插件提供的主色、透明度及样式属性。正文 URL 图片能关联附件后可使用已有占位色元数据。 |
| [Enhanced Responsive Images](https://wordpress.org/plugins/auto-sizes/) | 保留 `srcset`、`sizes` 和浏览器原生懒加载。WordPress 6.7 已纳入 `sizes=auto`；插件的部分增强面向区块主题，经典主题不会因此自动获得区块模板布局推导。 |
| [Image Prioritizer](https://wordpress.org/plugins/image-prioritizer/) | 保留原生 `loading`、`fetchpriority`、尺寸和 picture 候选，不再被主题懒加载覆盖。依赖 Optimization Detective、可用的 REST 接口及不同屏幕宽度的真实访客数据，安装后不会立即对每张图片产生调整。 |
| [Instant Back/Forward](https://wordpress.org/plugins/nocache-bfcache/) | 保留普通整页导航。真实站点的访客前进/后退缓存已验证可用；登录状态仍由插件的选择加入策略及浏览器条件决定。 |
| [Speculative Loading](https://wordpress.org/plugins/speculation-rules/) | 保留插件输出的推测规则和普通链接导航。是否执行预取/预渲染由规则、访客状态及浏览器决定。 |

以上适配不会改动插件选项。隔离 HTML 文档内部由文档自己管理的图片、外链图片和其他 CSS 装饰背景不走正文附件处理流程。

## 验证

- 使用真实官方插件和实际生成的媒体文件通过 14 项 PHP 图片集成检查。
- 4 个浏览器流程覆盖 Markdown 与原生区块、两种灯箱、手机宽度、全部封面持续可见和缓存重载、关闭 JavaScript 的 Banner，以及推测规则和检测脚本。
- 原有主题回归与发行包安装检查继续执行，测试入口和版本见 [测试说明](../tests/README.md)。

升级后应清理页面缓存，确保页面和编译资源同时更新。主题最低要求仍为 WordPress 6.6 / PHP 8.2，安装官方性能插件时另需满足各插件的版本要求。
